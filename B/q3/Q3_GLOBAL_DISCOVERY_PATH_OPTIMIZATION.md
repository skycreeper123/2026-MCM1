# Q3 全局发现与自适应路径优化方案

## 1. 文档目的

本文用于指导问题三下一版实现。目标不是删除当前算法的安全性，而是把当前的“发现一个源后立即服务”改为：

```text
全局发现 -> 保存所有源的保守定位区域 -> 联合选择测向和清除任务 -> 全局路径规划
```

当前 152 点条带保留为异常回退和安全基线，不作为正常清除方法。

本方案不得使用模拟器真值坐标、真实源位置或事后成功点来规划路线。

## 2. 当前问题定位

当前 `v2_local` 已经能够保证完整清除，但存在三个主要性能问题：

1. 一个扫描站发现源后，当前批次源会先被服务，清除后再回到扫描路线，造成额外往返。
2. `max_optimized_clear_attempts_per_source=8` 较小，许多局部区域需要超过 8 个网格点时会直接放弃局部计划。
3. 第二检测点主要按照定位区域半径选择，没有直接估计后续清除点数量、清除路线和返回扫描路线的代价。

最近 12 次演练的主要数据为：

| 指标 | 当前结果 |
|---|---:|
| 源总数 | 159 |
| 清除率 | 100% |
| 每局平均定位清除时间均值 | 419.666 s/源 |
| 按全部源加权平均 | 415.042 s/源 |
| 清除尝试 | 598 |
| 失败清除 | 439 |
| fallback 清除尝试 | 353 |
| 移动时间占比 | 86.694% |
| 规划计算时间 | 2.660 s/局 |

因此优先优化对象是清除路线和服务顺序，不是继续压缩几何计算时间。

## 3. 总体架构

下一版增加策略名 `v3_global`，保留以下两个策略作为对照：

```text
b0_serial      安全基线：发现后立即条带清除
b0_batch_fifo  批内 FIFO：完成一个站点扫描后服务该站发现的源
v2_local       当前版本：批内局部定位加条带回退
v3_global      本文方案：全局发现、联合定位和路径规划
```

`v3_global` 的状态机如下：

```text
DISCOVERY
    七个覆盖站完成扫描
    记录所有 direction 源的第一次检测约束
    记录所有 no_signal 约束

LOCALIZE_SERVICE
    在所有已发现源中选择下一个测向或清除任务
    实际收到响应后立即更新对应定位区域
    区域满足清除条件后生成服务计划

ROUTE_EXECUTION
    根据当前机器狗位置和频道状态选择下一个服务计划
    完成一个源后重新计算剩余任务顺序

EMERGENCY_FALLBACK
    仅在安全几何计算失败、局部计划失败或没有可验证覆盖计划时使用
    使用现有 152 点条带，不能在正常路径中主动调用
```

不要求所有源都先完成精确定位再清除。更好的方式是：先完成全局发现，然后在所有源的“下一次安全测向”和“局部清除”之间动态选择。

## 4. 具体代码改动

### 4.1 `planner.py`

#### 4.1.1 增加全局发现策略

增加：

```python
SUPPORTED_STRATEGIES = (
    "b0_serial",
    "b0_batch_fifo",
    "v2_local",
    "v3_global",
)
```

`v3_global` 完成七个覆盖站后，才进入定位和服务阶段。扫描阶段只做检测，不执行方向型源的清除。

每个 `ChannelRecord` 至少保留：

```text
anchor_position
anchor_bearing_deg
outer_vertices
no_signal_station_ids
measured_positions
region_version
service_plan
```

`direction` 源不能再因为当前站扫描结束而立即进入 FIFO 服务队列。

#### 4.1.2 修改源数量上界停止逻辑

当前逻辑只有在成功清除数量达到 16 且不存在 `DETECTED` 源时，才利用源数量上界标记未知频道不存在。

全局发现阶段应改为：

```text
detected_count + cleared_count >= source_count_upper_bound
```

时，可以将剩余 `UNKNOWN` 频道安全标记为 `ABSENT`，但不能把仍处于 `DETECTED` 状态的频道标记为已完成。

原因是：题目只限制源总数，不要求源必须先清除才能利用数量上界。

#### 4.1.3 增加全局任务表

建议在 `Q3Planner` 中增加：

```python
pending_sources: set[int]
service_plans: dict[int, ServicePlan]
active_task: Task | None
```

`pending_sources` 保存已经发现但尚未清除的源。服务顺序不再直接使用 `batch_channels[0]`，而是由任务选择器计算。

#### 4.1.4 增加任务选择器

每次动作前生成候选任务：

```text
候选任务 A：对源 i 做一次安全测向
候选任务 B：执行源 i 的 MEC 单点清除
候选任务 C：执行源 i 的局部网格清除
候选任务 D：前往下一覆盖站继续发现
```

任务评分使用保守估计：

```text
任务代价 = 当前点到任务入口的移动时间
         + 检测时间
         + 频道切换时间
         + 后续清除路线时间
         + 失败清除时间上界
         + 服务结束到下一任务入口的移动时间
```

不得使用真实源坐标计算任务代价。

### 4.2 `localize.py`

#### 4.2.1 保留现有安全候选点机制

第二检测点仍必须满足：

```text
对当前保守定位区域中的任意可能源，检测点距离不超过 1000m 的安全范围
```

不能为了缩短路线而直接把检测点放到不保证接收的位置。

#### 4.2.2 修复候选点简单截断问题

当前逻辑：

```python
unique = unique[:candidate_limit]
```

会导致候选方向不对称。应改成空间均匀保留：

1. 保留安全见证点；
2. 保留当前点或下一覆盖站方向点；
3. 保留示向线两侧候选；
4. 从剩余候选中使用最远点采样或角度均匀采样；
5. 最后才应用 `candidate_limit`。

初版也可以先把 `q2_candidate_limit` 从 12 提高到 16，但最终应修复候选筛选逻辑，而不是无限增大候选数。

#### 4.2.3 增加自适应覆盖计划

现有 `build_cover_plan()` 可以继续复用，但需要补充以下输出：

```text
cover_certificate
point_count
cover_radius_upper_m
entry_point
exit_point
route_distance_m
completion_upper_s
```

计划生成流程：

1. 如果最小包围圆半径不超过 `19.9m`，生成一个 MEC 单点计划；
2. 否则计算当前凸区域的最小方向包围矩形；
3. 使用不超过 `28m` 的网格单元；
4. 根据区域实际长度和宽度生成最少网格点；
5. 选择进入点和离开点，使其适配全局路线；
6. 验证整个区域到最近清除点的距离上界不超过 `19.9m`；
7. 验证通过后才允许执行。

覆盖点数量不能硬编码为 152。152 点条带只处理异常情况。

#### 4.2.4 增加完成时间评分

当前主要评分定位区域半径，需要增加：

```python
completion_upper_bound(region, candidate, continuation_target, config)
```

评分至少包括：

```text
移动到第二检测点的时间
第二次检测时间
最坏响应下的新区域覆盖点数量
局部覆盖路线时间
失败清除时间上界
离开当前源后的移动时间
```

候选点选择目标改为：

```text
最小化保守完成时间上界
```

不能只最小化 `worst_updated_cover_radius_m`。

### 4.3 `geometry.py`

#### 4.3.1 保留条带函数，但降低其策略优先级

`strip_clear_points()` 和 `strip_coverage_bound_m()` 暂时不要删除，因为它们提供当前最清晰的完整覆盖证明。

但在 `v3_global` 中，只有以下情况可以调用条带：

```text
初始区域几何失败
安全测向点不存在
局部覆盖计划没有通过覆盖证书
已验证局部计划执行失败
数值异常或协议异常
```

正常情况下不得因为“预计局部计划点数较多”就直接主动使用条带，而应先尝试安全测向缩小区域。

#### 4.3.2 暂不直接改动 28m 网格上限

`28m` 的半对角线约为 `19.8m`，低于 `19.9m` 安全清除半径。除非重新完成边界验证，否则不能增大 `local_grid_cell_m`。

## 5. 路径规划方法

### 5.1 服务计划表示

每个已发现源生成一个或多个服务计划：

```python
ServicePlan(
    channel=channel,
    localization_points=(...),
    clear_points=(...),
    entry_point=(...),
    exit_point=(...),
    point_count=...,
    route_distance_m=...,
    completion_upper_s=...,
    guaranteed=True,
)
```

一个服务计划必须只依赖当前已经获得的检测结果。

### 5.2 初版路径排序

源数量最多 16 个，初版不需要直接使用复杂整数规划。建议采用：

```text
最近任务优先
    -> 计算每个任务的保守完成代价
    -> 选择代价最小任务
    -> 执行并更新当前位置和区域
    -> 对剩余任务重新排序
```

路线稳定后，再增加 2-opt 或插入式改进：

```text
当前路线 A -> B -> C
尝试替换为 A -> C -> B
只有保守总时间下降时才接受
```

不能提前知道源清除成功点，因此不能使用成功点作为路径优化输入。

### 5.3 后续优化目标

在固定服务计划集合下，可以将任务排序近似为带入口、出口的 TSP/GTSP：

```text
每个源是一个服务任务
每个服务任务可能有多个候选入口和出口
目标是最小化总移动时间和动作时间
```

但第一版先使用贪心加动态重排，保证容易验证。

## 7. 实验矩阵

所有候选方案必须使用相同案例集，与 `v2_local` 做配对比较。

### 实验 A：局部清除上限

```text
max_optimized_clear_attempts_per_source = 8, 12, 16, 24
```

### 实验 B：额外测向次数

```text
max_extra_measurements_per_source = 2, 3, 4
```

### 实验 C：停止阈值

```text
minimum_radius_improvement_fraction = 0.03, 0.05, 0.10
```

### 实验 D：候选点规模

```text
q2_candidate_limit = 12, 16, 24
```

### 实验 E：完成时间评分

```text
半径评分
半径 + 移动时间
完整完成时间上界
```

### 实验 F：服务顺序

```text
FIFO
最近任务优先
最近任务优先 + 2-opt
```

每次实验必须记录：

```text
清除率
平均虚拟时间
加权平均虚拟时间
P95 和最大值
总移动距离
失败清除次数
fallback 次数
局部覆盖点数量
额外测向次数
规划现实时间
```

## 8. 正确性验收标准

候选版本必须同时满足：

1. 所有已有 Q3 单元测试继续通过；
2. 固定随机案例全部清除；
3. 所有局部覆盖计划都有明确覆盖证书；
4. 第二检测点始终通过安全接收判定；
5. 真实源始终保守包含在当前定位区域内；
6. 出现局部几何失败时可以有限回退；
7. 不出现死循环、重复无效测向或条带耗尽后错误标记完成；
8. 与 `v2_local` 相比，清除率不能下降；
9. 在相同案例集上失败清除次数和 fallback 次数应显著下降；
10. 平均时间、P95 和最大时间至少有一项明显改善，且其他指标不能严重恶化。

## 9. 不采用的方案

暂不采用以下方案：

```text
直接删除 152 点条带而不给出新的完整覆盖证明
使用模拟器真实源坐标做路径规划
只按照一次实验中的成功点顺序设计固定路径
先训练深度学习模型再替代安全几何判定
为了减少计算时间而放宽 20m 清除约束
```

机器学习最多作为离线参数分析工具，不能替代 Q1/Q2 的保守几何约束和第三问的完整清除证书。

## 10. 实现顺序

建议队友按以下顺序提交：

```text
Commit 1：增加 v3_global 策略和全局发现阶段，不改清除几何
Commit 2：增加逐源服务计划和自适应 MEC/网格覆盖证书
Commit 3：增加安全测向任务和完成时间评分
Commit 4：增加全局任务排序和动态重排
Commit 5：增加 fallback 使用统计和配对实验脚本
Commit 6：完成边界、异常和随机案例验收
```

任何一步如果破坏清除率，都退回上一版本，不直接删除 `v2_local` 或 B0 安全基线。

## 11. 最终定位

本方案使用前两问的成果作为约束：

```text
Q1：构造第一次示向后的保守定位区域
Q2：选择安全的后续检测点并评估区域收缩
Q3：在所有源之间安排测向、清除和移动路线
```

第三问的最终主方法应是：

```text
全局发现 + 安全主动测向 + 自适应覆盖 + 全局路径规划
```

152 点条带只作为最后一层安全回退，不应成为正常实验中的主要清除方式。
