# Q3 全局发现与自适应路径算法总结（版本3）

记录日期：2026-09-11。当前默认策略为 `v3_global`。本文件参考 Q1、Q2 的 summary 组织方式，说明已经实现的模型、算法、接口、验证和适用边界。设计依据为 [全局发现与路径优化方案](Q3_GLOBAL_DISCOVERY_PATH_OPTIMIZATION.md)。

当前实现采用“全局发现 → 安全主动测向与局部清除联合选择 → 执行并动态重排”。实现见 `planner.py`、`localize.py`、`geometry.py`；运行器见 `runner.py`。`b0_serial`、`b0_batch_fifo` 和 `v2_local` 按设计要求保留为对照，152 点条带仅作为 V3 的异常回退。

## 1. 建模目标与时间指标

目标区域为半径 1800 m 的圆盘，1—20 频道中每频道至多一个静止全向干扰源，总源数上界为 16；题目正常案例为 10—16 个源。有效接收半径在 1000—1500 m 之间。初始位置为原点，检测频道为 1。

机器狗速度为 5 m/s，测向耗时 5 s，切换检测频道耗时 1 s，失败清除耗时 3 s，成功清除耗时 5 s。清除请求指定目标频道，不改变检测频道；只有 MEASURE 会更新检测频道和计入切换时间。

```text
T = L / 5 + 5 N_measure + N_switch + 3 N_failed_clear + 5 N_success
每局平均清除时间 = T / N_success
全部源加权平均 = 所有局的 T 之和 / 所有局的成功清除数之和
```

本算法目标是在完整发现和最终清除的约束下减少虚拟时间。现实中的规划计算时间单独记录，不混入虚拟时间。无源案例的平均清除时间为 `None`，不以 0 秒冒充平均成绩。

规划器只接收检测结果和清除反馈。测试中的真实坐标只由离线环境用于生成响应、验证包含关系，不作为任务排序、检测点选择或清除路径的输入。

## 2. 七站全局发现与结束证书

覆盖站由原点及半径 1150 m 正六边形的六个顶点构成；按环序访问时完整站点路线长 6900 m。`q3_coverage_certificate()` 给出目标圆盘到最近覆盖站的距离上界，小于保证接收半径 1000 m。

在每站仅扫描 UNKNOWN 频道，奇偶站分别升序、降序访问频道。返回 direction 后保存首测位置、示向度、保守区域与观测记录；返回 near 后保存一个 5 m 范围的清除证书。两类源均进入全局 `pending_sources`，发现阶段不执行清除。direction 源不进入本站 FIFO 队列。

返回 no_signal 时保存该频道的站点 ID。只在七个站都获得 no_signal 后标记 ABSENT，或者在已发现数加已清除数达到 16 时，通过源数上界将剩余 UNKNOWN 标记 ABSENT。后一条件允许省略已经没有必要的扫描和站点移动，但 DETECTED 频道仍必须完成服务。

全部频道处于 CLEARED 或 ABSENT，且没有模型、协议或时间预算异常，才有完成证书。`/exit` 被接受与任务完成是两个不同字段；退出成功不能代替完成证书。

## 3. 首测外包与累计定位

对于首测位置 S₁ 和读数 θ₁，区域满足：

```text
G ∈ W(S₁, θ₁, 1.005°) ∩ B(O, 1800) ∩ B(S₁, 1500) ⊆ P₁⁺
```

圆盘采用 128 边外切多边形，半平面交与裁剪复用 Q1、Q2 的几何接口。1.005° 在题设 ±1° 上预留示向读数保留两位小数的量化裕量，不是改写题目的物理误差。

后续 direction 响应将当前外包与新测点的示向角域、1500 m 接收圆外包取交，得到 Pₖ₊₁⁺。原首测锚点始终保留，`region_version` 随有效 direction 更新增长。空区域或数值异常不会把源标记已清除，而会转入异常处理。

no_signal 的站点证据予以保留；本版不将“接收圆外部”这类非凸排除区域直接裁入凸外包。这样会损失部分定位信息，但不会错误地删除真实可能位置。清除失败也不直接以非凸圆外约束修改外包，而是继续已经验证的覆盖计划。

## 4. 安全测向与候选点筛选

后续检测点 s 必须满足：

```text
max ||s − v|| ≤ 999.9 m，v 遍历当前外包 P⁺ 的所有顶点
```

到固定点的距离是凸函数，在凸多边形上最大值取于顶点。因此这一判定覆盖区域内的任意可能源，预留 0.1 m 接收裕量。安全区域的最小包围圆心作为见证点。

候选池包含见证点、安全的当前位置、可用的续接位置，以及相对首测示向每隔 30° 的 12 个径向安全边界代表点。排除已在同频道测过的位置，并再次验证安全性。

候选数受限时，按“见证点 → 路线代表点 → 示向线两侧代表点 → 最远点分散采样”保留，修复原先按列表前缀截断导致的方向不对称。默认 16 是候选上限，实际候选数可能更少；调大上限不等于一定生成更多点。

## 5. 连续响应下的完成时间评分

V3 使用 `completion_upper_bound()` 评价“前往候选点检测，然后执行一个有证书的覆盖方案”的最坏完成代价，不再只按定位半径排名。

可能的读数范围由顶点方位的最短覆盖弧外扩角误差得到；测点位于区域内部、顶点邻近或不能落入开半圆时，使用完整 360°。默认划分 32 个读数区间。对任意区间 I=[m−h,m+h]：

```text
P⁺ ∩ W(s, θ, δ) ⊆ P⁺ ∩ W(s, m, δ+h)，对任意 θ∈I
```

对每个区间外包构造 MEC 单点或首测方向矩形网格，取各区间的最大覆盖路线及动作时间；near 分支单独计入原地成功清除时间，不将 near 解释成零耗时。若 δ+h≥90°，使用完整当前区域作为保守外包。

计算超时时，未完成的响应范围由整个当前区域的覆盖计划接管，不能简单丢弃未计算的角度。评分包含当前点到检测点的移动、5 s 检测、后续覆盖路线、最多 N−1 次失败及一次成功清除。调度器再加实际检测频道切换时间，以及到另一个可行服务入口的保守离开代价。

检测候选的几何评分按源和区域版本缓存。当前位置、检测频道和续接入口变化时重新计价，不复用过时的移动成本。离开代价检查所有可能清除点，包括提前成功的位置，而不假定总是在网格最后一点成功。

该数值是一个可行“检测后覆盖”策略的保守代价，用于比较任务；它不是未知官方案例真实完成时间的预测，也不是未来整个自适应调度流程的严格总时间上界。浮点几何带数值裕量，尚非区间算术形式化认证。

## 6. 自适应局部覆盖与证书

先计算并复核外包的最小包围圆。半径加数值裕量不超过 19.9 m 时，直接在圆心生成一个清除点。单点证书验证所有区域顶点到该圆心的最大距离。

否则枚举凸区域边方向、首测方向和坐标轴方向的包围矩形，其中包含最小面积方向矩形的候选。对每个矩形沿两轴等分，单元边长均不超过 28 m，以所有单元中心作为清除点：

```text
N = ceil(矩形长度 / 28) × ceil(矩形宽度 / 28)
覆盖距离上界 = sqrt(单元长² + 单元宽²) / 2 ≤ 19.9 m
```

实际计算先对矩形边界外扩 1e−7 m，再取整划分，防止浮点边界误差令单元超过 28 m。不会删掉位于目标圆外或凸区域外的网格中心，因为这些中心可能承担边界处的覆盖。

初建计划时比较两种扫描轴和四角入口形成的八种蛇形遍历，并在候选矩形中选取完成代价较低的计划。重排时复用覆盖几何，重新比较路径正反两个方向，更新进入和离开的移动成本；不在每次重排时重新计算全部矩形。

`cover_certificate` 包含证书方法、矩形方向、投影边界、单元数量及覆盖半径上界。执行前，`verify_cover_certificate()` 检查整个凸区域位于矩形内、半对角线满足清除半径，并检查每个单元中心恰好存在。只检查区域顶点到最近网格点是不充分的，本版不采用这种错误的多圆覆盖判据。

默认 `max_optimized_clear_attempts_per_source=16` 在 V3 中作为优先再次测向的点数阈值：当当前网格超过阈值且仍有可行测向任务时，先尝试缩小区域。测向次数、路线或计算预算耗尽时，仍可执行超过 16 点的已验证自适应局部网格。这个阈值不是 V3 的硬中止上限，避免因网格点数较多而主动调用 152 点条带。V2 对照仍按旧逻辑将 8 点作为优化尝试上限。

## 7. 全局任务表与动态顺序

每个源保存 `anchor_position`、`anchor_bearing_deg`、`outer_vertices`、`no_signal_station_ids`、`measured_positions`、`region_version`、`service_plan`。规划器另外维护待处理源集合、服务计划表和当前任务。

发现完成后，每次调度为各待处理源生成安全测向任务及当前可行清除任务；异常源生成回退任务。完成时间较小的任务先执行，平局按频道及位置确定，保证可复现的离散选择。

收到一次新的 direction 响应后更新区域并释放当前源，允许在所有剩余源之间重新选择。开始清除计划后，在同一源的完整覆盖路径中连续执行，直到成功或计划耗尽；清除成功后从待处理集合移除该源，再全局重排。near 响应已有单点证书，可直接完成当前服务。

续接入口来自其他源当前有证书的服务计划，未使用真实源位置或事后成功点。下一轮会根据实际当前位置重新决定任务，因此这是带一步后续移动估计的贪心调度，不声称 TSP/GTSP 全局最优。初版按设计第 5 节采用动态贪心；2-opt、整数规划和机器学习均未加入主流程。

## 8. 异常回退与有限性

只有初始几何失败、后续数值异常、没有可验证局部计划、安全测向出现异常响应或已验证清除计划耗尽等情况，V3 才调用首测 152 点条带。正常大网格不会仅因超过 16 点而触发条带。

条带沿首测示向前进至 1500 m，纵向间距 20 m，两侧偏移为 −15 m 和 +15 m；`strip_coverage_bound_m()` 保留其连续覆盖距离证明。条带耗尽仍未成功，或 near 后清除失败，均报告 `MODEL_OR_PROTOCOL_INCONSISTENCY`，不伪造已完成状态。

每源额外测向最多 3 次，已测位置不能重复；连续两次区域半径相对改善不足 3% 时停止继续测向。额外测向路径按首测锚点累计的闭合路线不超过 4000 m；这个量不是全局总移动距离，也不是 V3 最终覆盖网格的总路线预算。

规划单次预算默认 1.5 s，总规划预算默认 60 s。预算用于限制进一步搜索，预算不足仍优先执行已验证的局部覆盖。预算是协作式检查，不能硬中断单次几何调用。

`q3_baseline_upper_bounds()` 仍报告 B0 默认 19340 s 的保守界；它不能直接当作 V3 的总时间界。`q3_global_upper_bounds()` 单独给出按有限测向数、有限网格数和位置范围推导的非常宽松有限界，仅用于自检，不作为性能预计。

## 10. 接口与使用方式

```python
from B.q3 import Q3Config, Q3Planner

planner = Q3Planner(Q3Config())
action = planner.propose_action()
# 只将经过协议校验且已被接受的响应应用一次：
# planner.apply_measure_result(action, "direction", svd_deg)
# planner.apply_clear_result(action, "success")
# planner.apply_exit_result(action)
print(planner.summary())
```

重复 `propose_action()` 返回同一待执行动作，直到响应被应用；禁止重复应用同一响应。网络重试保持相同请求 ID 和完全相同请求体，避免请求是否执行不明时错误推进状态。

| 对象 / 字段 | 输出内容 |
| --- | --- |
| `Q3Action` | 动作、频道、位置、目的、区域版本与决策依据 |
| `ServicePlan.as_dict()` | 源频道、区域版本、清除点、入口与出口、点数、路线、时间与覆盖证书 |
| `pending_sources` | 已发现且尚未清除的源 |
| `task_history` | 已选择任务及候选数、续接位置与保守评分 |
| `cover_plan_history` | 实际启用的局部覆盖计划及证书 |
| `summary()` | 完成证书、移动、检测、清除、失败、回退、规划耗时等 |
| `fallback_reasons` | 按频道记录异常回退原因 |
| `local_cover_plan_point_counts` | 已启用局部计划的点数，区别于实际尝试次数 |

运行和网络设置见 [模拟器运行说明](RUN_SIMULATOR.md)。本次实现修改未连接或启动官方模拟器。
