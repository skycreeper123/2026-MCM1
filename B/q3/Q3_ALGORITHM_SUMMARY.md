# Q3 算法总结与实现交接 V2-local

更新日期：2026-09-11。已同步用户重新上传的 Q2 `algorithm_version=3`。

当前生产代码已经实现三个显式策略：`b0_serial`、`b0_batch_fifo` 和默认的 `v2_local`。V2-local 已包含本站批量扫描、FIFO连续服务、累计定位外包、Q2 V3连续响应半径上界选点、MEC/28m矩形覆盖、每源测量/清除/4000m路长额度，以及完整152点条带回退。runner 已区分 `exit_accepted` 与 `task_completed`，只有完成证书成立才报告任务完成。

尚未实现的是第4、6节更强的 `response_completion_bound` 连续完成时间上界、按完成秒数决定是否继续测向，以及 `V2_batch_order` 服务顺序评分；因此当前策略准确标记为 `v2_local`，不提前声称完成 `V2_time_score`。104点条带仍只作为设计消融，生产回退保持152点。完整公式、预算证明及后续验收项见 [Q3优化实现规范](Q3_OPTIMIZATION_SPEC_V2.md)。

## 1 推荐优化及已有证据

推荐路线：七站覆盖发现 → 本站所有未知频道集中检测 → 批次内连续服务各源 → 用累计定位区域比较清除与新增测向 → 预算耗尽时回到完整首次条带。

不优先改七站布置或频道切换。首次演练的主要成本是清除阶段的移动和587次失败尝试；也不把“再测一次”作为固定动作，因为第二次测向仍未必达到20m，少量光学覆盖可能更便宜。

| 证据 | 结果 | 适用范围 |
|---|---|---|
| 原B0真实演练 | 13/13；8134.791492s；625.753192s/源 | 单个官方演练案例 |
| 本站先扫完再按FIFO清除 | 重算7495.932525s；576.610194s/源；节省638.858966s（7.8534%） | 原日志的合法轨迹反事实，保持每频道位置、顺序和反馈；不是官方重跑 |
| 新版Q2本地回归 | 29项通过 | Q2 V3当前代码；Q3扩展回归当前27项通过 |
| 104点条带、28m格子覆盖 | 覆盖距离上界分别19.761148m、19.798990m | 解析与常数检查；尚非完整V2性能测试 |

FIFO反事实仍有587次失败清除，表明调度和定位两项优化应分别实现与评测。新测点不能沿用旧日志猜测方向反馈；Q2接入后的整体收益需要完整离线实验和新的演练。

本次实现验收另使用一个公开合成的10源边界/内部混合案例作配对闭环：`b0_batch_fifo` 为7961.050s、720次失败清除，`v2_local` 为4611.828s、6次失败清除，全部10源均清除。该单例只证明新代码路径可运行并展示潜在收益，不是官方演练成绩，也不能替代多案例统计。

复现证据：[核验结果](Q3_DESIGN_CHECKS_20260911.json)、[核验脚本](design_validation_20260911.py)。结果含输入哈希，不含队号及官方加密日志内容。

## 2 Q2 V3 接入说明

Q2 V3 保留连续示向响应区间外包，并增加多起点、32→128→256区间分级评分、局部方向搜索以及可选的信息扩展候选域。对每个候选点，`worst_updated_cover_radius_m` 仍是全部direction响应的保守半径上界；`ranking_is_discrete_approximation=true` 只说明测点位置搜索有限。Q3当前固定使用保守的 `fixed` 收信区域，并为实时性将累计选点限制为12个候选、32个响应区间。

Q3接入时必须明确：

- Q2默认移动权重已变为λ=0（精度优先）。Q3追求总耗时，不能直接把这个默认当作最优策略。最小适配可显式λ=1作对照；最终按第4节比较剩余虚拟秒数。
- Q2默认 `error_deg=1.0`，Q3继续显式传1.005，将两位小数量化裕量统一到首次外包、实际更新和候选评分。该参数不属于 `Q2Config` 字段。
- `choose_second_detection` 仍仅接受首次观测；传入历史已测位置只会防重复，不会累计观测。第三点须基于累计外包，不能反复从第一条观测重建。
- `B.q2.response_radius_bound(vertices, candidate, ...)` 与 `clip_convex_polygon` 已作为公共接口导出；Q3的 `localize.py` 用其评价累计外包并增量加入实际方向及1500m接收圆约束。
- `status=OK` 可以同时 `timed_out=true`；`selection_mode=safe_fallback` 表示安全但未必有信息增益。预算是协作式全调用预算，不是硬实时截止。
- Q2 V3新增多起点与分级区间参数；Q3不照搬其离线默认规模，而使用独立、显式的实时缩减配置。
- Q2安全域保证全向源收信，不保证二次观测就能清除。实际clear中心和覆盖半径只能在真实反馈到达后计算。

Q2调用形式：

```python
from B.q2 import Q2Config, choose_second_detection

r = choose_second_detection(
    first_observation={"position": {"x": ax, "y": ay}, "svd_deg": theta},
    error_deg=1.005,
    current_position={"x": px, "y": py},
    used_positions=used_positions_for_this_channel,
    config=Q2Config(movement_weight_m_per_s=1.0,
                    calculation_time_limit_s=1.0),
)
```

当前Q2接口严格校验字典字段。当前位置必须传实际狗位置；历史点按频道保存，不应禁止不同频道在同点测量。Q3的依赖从B0纯标准库扩展到NumPy、SciPy。

本次公开探测以首测(0,0)、示向0°、1.005°为输入，分别运行λ=0和λ=1，并各检查72个保守角域场景。两种设置都出现二次交会后半径超过20m的情况，安全点及连续半径上界交叉检查通过。最终复跑两组均未耗尽5秒预算，λ=0与λ=1的连续半径上界分别为57.337m、86.060m，移动时间分别为198.079s、148.160s。限时搜索候选可能受机器速度影响；具体数字、预算状态以核验JSON为准，不把有限场景比例当真实成功率。

## 3 批处理和单源服务规则

保留原点加半径1150m正六边形的七站，最坏发现距离988.511m<1000m，原开放站间路线6900m。

每站分为SCAN和SERVICE：

1. SCAN阶段原地扫描全部UNKNOWN频道。direction存入本批待服务队列后继续扫描；near原地立即清除，再恢复扫描。
2. 本站扫描结束后逐源服务。先实现FIFO；后续再用“服务一个源并接上下站”的代价排序。单个源服务到成功或明确异常再换源。
3. 本批已发现源全部解决后，从实际位置直接去下一覆盖站，不发回站用的多余测量。本版不跨站积压已发现源。

单源使用所有有效direction构造凸外包：目标圆外包 ∩ 全部±1.005°前向角域 ∩ 全部1500m接收圆外包。每次更新后：

- 重新核验包围圆覆盖半径≤19.9m：可在圆心清除。
- 否则比较少量完整区域覆盖、补充安全测向和原条带。
- 区域覆盖采用矩形外包，每个小格边长≤28m，在格中心清除，覆盖距离≤19.798990m。完整计划必须满足剩余优化次数及路长额度。
- 安全点无信号、几何异常、保证清除意外失败，禁用该源主动几何并有限回退。完整原条带耗尽则报告不一致，不伪报完成。

初版保留已演练的152点条带。104点方案另设消融开关：每行52点，纵向1500k/51，横向±13.2m；解析保证成立，待端点、旋转、量化及序列化测试后再启用。

不要因为清除点在目标圆外而删点；圆外点也可能覆盖圆内源。不能凭两个示向中心线交点或“直径≤40m”直接清除。

## 4 利用Q2连续区间改进Q3时间决策

对无需新增测向的合法终止计划Q，计算包含接上下站b的上界：

```text
U(Q; p,b) = 完整路径长度(p→Q→b)/5 + 3*清除点数 + 2
```

最后站去掉接b的路段。提前成功后直接去b不会超过该完整路径，故该界可执行。

对第二或第三测点s，复用Q2的完整读数区间。每个区间I构造能覆盖其全部可能更新区域的外包E(I)，再为E(I)缓存一个满足预算的终止清除计划。候选比较：

```text
J_upper(s) = 移动到s/5 + 检测5秒 + 实际切换费
             + max(各读数区间的终止计划时间上界, near分支时间)
```

所有叶区间必须覆盖完整读数域；子区间计算未完成则保留父区间与原计划。只有最好的新增测量计划上界比当前终止计划至少少10秒且预算允许，才继续测量。该规则比较保守上界，不声称每个真实案例都比B0更快。

这是拟新增的 `response_completion_bound`，当前Q2只有半径上界，不返回清除时间上界或缓存计划。不能把单个半径值乘常数冒充完成时间。完整构造和保证条件见详细规范第6节；尚未实现此接口时，应明确标记为最小适配版本。

## 5 状态、预算与实现陷阱

推荐初值：每源首次发现后最多3次额外测量、8次优化清除、4000m优化路长（含虚构回本批站的计费距离）；整局选点计算目标上限60s、单次目标1s、退出余量30s。near所需的一次清除也预留额度。参数待调，现实计算预算不是硬保证。

在七站固定、本站目标服务完再前进、优化额度严格执行且合法动作有时间执行的条件下，保留152点回退的V2松上界为33068s、2750个逻辑请求。它不同于B0的19340s、2574请求；提高性能需要实测，不能拿较松上界作提速证明。

实现必须处理以下当前代码耦合：

- 新增测量purpose：COVERAGE_SCAN与LOCALIZE。当前 `apply_measure_result` 无条件推进扫描游标，接入定位测量后必须修正。
- 首次anchor保持不变；追加observations、region_version、该频道历史测点。不能把定位no_signal写进station_id=None的扫描证书。
- 服务队列仍有DETECTED时不能完成；16个不同频道clear成功可凭总数上限结束，否则每个空频道需七站证据。
- `runner.py` 当前把接受EXIT直接视为completed。改为分别记录exit_accepted和task_completed，后者必须有全部解决证书；模型异常、预算不足都不算完成。
- 规划前检查剩余现实时间并传给选点层；重复propose和重试不得改变待定动作坐标，也不重复推进计数。
- 实际路长与“用于证明的虚构回站路长”分开计账；clear不切频道，成败都更新位置。

## 6 后续Agent的实施顺序和证据问题

按独立开关逐步实现：`B0_batch_fifo → V2_local → V2_time_score → V2_batch_order`；104点条带单独消融。每一步保留B0，同一公开案例和固定位置误差函数配对评测。先验收无漏源、无错误完成与精确时间账，再比较总时间、P95、路径和失败清除次数；不单独追求首次清除成功率。

新增接口/模块见详细规范第2、8节；关键验收包含累计观测选第三点、near恢复扫描、LOCALIZE不跳频道、连续响应时间界、预算中途细分、完整覆盖与异常回退。

当前代码回归中Q2为29项、Q3为27项，均通过。上游保存的大规模验证结果仍应按其元数据哈希独立核对；本次没有重跑200例验证，不能把旧结果标为当前Q3文件组合重新产出。
