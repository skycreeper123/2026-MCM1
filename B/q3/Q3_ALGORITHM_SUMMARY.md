# 问题三当前算法框架总结

更新日期：2026-09-11。本文说明问题三的当前算法框架，供后续 Agent 实现。问题三只考虑全向干扰源。

当前 `planner.py`、`geometry.py` 和 `runner.py` 仍是首次演练使用的 B0 代码；本文包含已经确定的新框架接口，尚未写入生产规划器的部分会明确说明。

## 1 任务与总体流程

目标区域为半径1800m的圆盘。干扰源共10至16个，具体数量未知；每个源占用不同频道，频道范围为1至20。有效接收半径位于1000至1500m之间。机器狗从原点出发，测向机初始频道为1，移动速度为5m/s。

总体流程为：

```text
进入模拟器
→ 访问七个覆盖站
→ 在当前站扫描所有未知频道
→ 保存本次发现的频道
→ 逐个定位并清除本批频道
→ 前往下一个覆盖站
→ 所有频道获得清除或不存在证书
→ 主动退出
```

检测返回 `near` 时原地清除，然后继续当前站扫描。返回 `direction` 时保存观测并加入本批待处理队列。返回 `no_signal` 时只保存本站证据。

## 2 七站覆盖与频道发现

覆盖站为原点和半径1150m正六边形的六个顶点：

```text
V = {(0,0)} ∪ {1150(cos(kπ/3), sin(kπ/3)) : k=0,...,5}
```

中心站覆盖半径1000m以内区域。外圈源到最近环站的最坏距离为988.511m，小于最小接收半径1000m，因此每个尚未清除的全向源至少能在一个覆盖站被检测到。

路线从原点依次访问六个环站，不返回原点，站间基础路长6900m。相邻站使用升序、降序交替的频道顺序。每站只扫描状态为 `UNKNOWN` 的频道。

当前站完成全部未知频道扫描后，才处理本次发现的频道。所有本批频道处理完成后，从机器狗实际位置直接前往下一覆盖站。

## 3 状态与测量用途

频道业务状态为：

```text
UNKNOWN → DETECTED → CLEARED
UNKNOWN → ABSENT
```

已发现频道另有处理阶段：

```text
READY_CLEAR / LOCALIZING / COVERING / FALLBACK
```

- `UNKNOWN`：未发现，也没有完整不存在证书。
- `DETECTED`：已得到 `direction` 或 `near`，尚未成功清除。
- `CLEARED`：清除响应为 `success`。
- `ABSENT`：具有七站无信号证书，或清除成功数达到16后由总数上限判定。
- `READY_CLEAR`：当前位置已经具有20m内的清除保证。
- `LOCALIZING`：正在增加安全测点和示向约束。
- `COVERING`：正在执行覆盖当前定位区域的有限清除点列。
- `FALLBACK`：执行首次示向对应的完整保证条带。

测量动作必须标记用途：

```text
COVERAGE_SCAN
LOCALIZE
```

只有 `COVERAGE_SCAN` 的合法响应能够推进站内频道游标，并将 `no_signal` 记入覆盖站证据。`LOCALIZE` 只更新对应频道的定位信息。

## 4 定位区域

每个正常示向频道保存第一次检测位置和示向度作为不可变锚点，之后的有效观测追加到历史中。

程序维护包含真实源的凸外包：

```text
P+ = 目标圆外包
     ∩ 所有direction观测的前向角域
     ∩ 所有direction测点的1500m接收圆外包
```

示向角域统一采用半宽1.005°。目标圆和接收圆使用外切正多边形，默认128边。每次新增 `direction` 后增量裁剪，新增约束不能使外包扩大；原始观测必须保留，以便几何异常时重新构造。

`no_signal` 暂不裁剪主凸外包，因为排除接收圆会形成非凸区域。清除失败也只保存证据。若外包为空、顶点非有限或几何计算异常，该频道转入首次锚点条带。

## 5 Q2算法对Q3的作用

第一次得到 `direction` 后，第二检测点使用本地Q2算法：

```python
from B.q2 import Q2Config, choose_second_detection

result = choose_second_detection(
    first_observation={"position": {"x": ax, "y": ay}, "svd_deg": theta},
    error_deg=1.005,
    current_position={"x": px, "y": py},
    used_positions=used_positions_for_this_channel,
    config=Q2Config(
        movement_weight_m_per_s=1.0,
        calculation_time_limit_s=1.0,
    ),
)
```

Q2安全候选点到初始外包内任意可能源位置均不超过999.9m，因此对全向源保证再次收信。Q2当前版本用连续示向响应区间计算保守定位半径上界；`worst_updated_cover_radius_m` 覆盖全部可能的 `direction` 返回。有限性只存在于候选测点搜索。

接入时注意：

- Q2默认 `error_deg=1.0`；Q3必须显式传1.005。
- Q2默认移动权重为0；Q3调用时显式设置所用权重，并在运行配置中记录。
- `choose_second_detection` 只根据首次观测构造区域，只直接用于第二点。
- 第三点及以后必须基于当前累计外包，不能反复从第一次观测重建。
- 同一频道不能在同一位置重复检测；不同频道可以使用相同位置。
- `status=OK` 可同时出现 `timed_out=true`；安全后备点保证收信，但不一定能明显缩小区域。

后续检测点需要以下接口：

```text
update_outer_region(previous_vertices, observation, error_deg,
                    maximum_receive_radius_m) -> RegionResult

choose_detection_from_region(vertices, current_position, used_positions,
                             next_station, config, deadline) -> CandidateResult
```

每个频道首次发现后最多增加3次定位测量。无安全未测点、区域收缩停滞、达到次数上限、计算预算不足或几何异常时，结束定位阶段。

## 6 清除方案

对当前外包求覆盖圆，并重新计算全部顶点到圆心的最大距离。只有覆盖半径不超过19.9m时，才在圆心执行保证型清除。

若不能单点覆盖，可用矩形外包生成有限清除网格。将矩形划分为边长不超过28m的小格，在格中心清除；任意格内点到中心不超过：

```text
14√2 = 19.798990m
```

只有完整网格不超过剩余主动清除额度时才能执行。每个频道默认最多8次主动阶段清除，包括单点清除、局部网格和定位测量返回 `near` 后的原地清除。

主动定位和局部覆盖不能完成时，使用首次锚点的完整条带：

```text
q(k,-) = anchor + 20k*u - 15*n
q(k,+) = anchor + 20k*u + 15*n
k = 0,...,75
```

共152点，真实源距最近点的理论上界约18.028m。第一次示向锚点不得被后续观测覆盖。152点全部失败时报告 `MODEL_OR_PROTOCOL_INCONSISTENCY`，不能标记已完成或重新循环。

104点条带可作为独立配置：每行52点，纵向位置为1500k/51，横向偏移±13.2m，解析覆盖距离19.761148m。启用前需通过端点、旋转、角度量化和坐标序列化测试；当前默认回退仍为152点。

## 7 动作选择与批内顺序

对当前清除点列Q，计算完整执行并接上下一个覆盖站的时间：

```text
U(Q; p,b) = 完整路径长度(p→Q→b)/5 + 3N + 2
```

最后一站不计到后继站的距离。式中N为清除点数，表示前N−1次失败、最后一次成功。

对安全检测点s，计算：

```text
J(s) = 到s的移动时间 + 检测5秒 + 实际频道切换时间
       + max(direction各响应区间的后续清除时间, near分支时间)
```

每个direction响应区间必须对应一个覆盖该区间更新外包的可执行清除计划。区间细分未完成时保留父区间及父计划。当前Q2提供连续响应半径上界，Q3还需实现 `response_completion_bound`，将响应区间与清除计划组合成时间上界。

若检测方案的完成时间上界比当前清除方案至少少10s，并且测量、清除、路长和现实时间预算均允许，则执行检测；否则执行当前清除方案。10s为配置参数。

本批频道基础顺序为发现顺序FIFO。处理一个频道期间不切换到其他频道；成功清除或明确异常后再处理下一个。若加入代价排序，只能使用当前已知位置和外包，不能使用模拟器真值或未来成功位置。

## 8 预算与停止证书

默认预算：

```text
每源额外定位测量：最多3次
每源主动阶段清除：最多8次
每源主动阶段闭合路长：最多4000m
单次选点计算目标：1s
整局选点累计计算目标：60s
主动退出预留：30s
```

主动阶段路长用“从本批覆盖站出发并虚构返回该站”的闭合距离证明上界；实际路长仍按真实当前位置单独记录。

保留152点最终条带时，上述框架的松虚拟时间上界为33068s，逻辑请求上界为2750。达到现实时间保护阈值时主动退出，标记 `TIME_BUDGET_INCOMPLETE`，不能报告任务完成。

完整停止证书只有两种：

1. 16个不同频道已经清除成功；
2. 所有20个频道均为 `CLEARED`，或具有七站无信号证书的 `ABSENT`。

成功执行 `/exit` 只说明接口正常退出。运行摘要应分别记录 `exit_accepted` 和 `task_completed`。

## 9 实现接口

保留现有单动作规划器接口：每次返回一个确定的 `MEASURE`、`CLEAR` 或 `EXIT`；只有响应合法且 `accepted=true` 后推进状态。重试期间动作位置、频道和请求内容不能变化。

需要实现：

```text
B/q3/localize.py
    累计外包、安全候选适配、覆盖圆、局部覆盖与响应完成时间

B/q3/planner.py
    SCAN/SERVICE阶段、批队列、定位状态、动作选择与预算

B/q3/runner.py
    规划截止时间、策略配置、exit_accepted/task_completed分离

B/q3/tests/
    累计定位、批处理、回退、停止证书与时间账测试
```

当前 `apply_measure_result` 会无条件推进扫描游标，加入 `LOCALIZE` 后必须按测量用途区分。当前运行器接受 `/exit` 后直接设置完成标记，也必须按停止证书修正。

Q3运行环境需要Q2使用的NumPy和SciPy。所有配置、动作原因、观测、定位区域版本、预算计数和实际时间账都应写入运行摘要。

当前生产实现仍是B0。后续Agent应以本文为Q3框架说明，并结合 [详细算法规范](Q3_OPTIMIZATION_SPEC_V2.md) 完成代码。
