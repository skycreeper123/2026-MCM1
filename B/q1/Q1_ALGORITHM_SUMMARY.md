# 第一问定位区域直径与直径圆覆盖算法总结

论文验证材料见 [Q1 结果验证与可视化](validation_results/Q1结果验证.md)，图表安排与复现方法见 [验证说明](VALIDATION_README.md)。

第一问包含两个核心计算任务：一是计算交会定位区域内任意两点的最大距离，即区域直径；二是判断以该直径为圆直径的圆能否覆盖整个定位区域。计算这两项之前，必须先把各检测点的 ±1° 示向角域求交，得到定位区域。

本目录的 Python 算法输入若干检测点坐标及示向度，输出纯前向角域交集的状态、顶点、直径、最远点对，以及直径圆覆盖结论。第一问不需要连接模拟器。

依据仓库 `26/B题/B题.pdf` 的问题一及附录二，以及 `b_algorithm_implementation_spec.md` 第 4.2、4.3、5 节。题面没有提供第一问的固定数值数据，`examples/` 均为合成示例。

## 问题拆分与算法逻辑

### 1 构造定位区域

每次检测不是一条无限直线，而是以检测点为顶点、示向度左右各扩张 1° 的前向角域。每个角域可以写成两个线性半平面，全部观测的半平面交集就是定位区域。

程序先用线性规划检查交集：无可行点返回 `EMPTY`；任一坐标方向无界返回 `UNBOUNDED`；只有交集非空且四个坐标方向均有界时才继续计算多边形顶点。这样不会把无界楔形误判为有限多边形。

### 2 计算区域最大直径

有界定位区域是凸多边形。凸多边形内两点距离的最大值一定在顶点对上取得，因此枚举全部顶点对，计算欧氏距离并取最大值：

```text
D = max ||v_i - v_j||
```

程序同时保存取得最大值的端点 `a、b`。当前参考实现复杂度为 O(v²)，适合第一问的小规模定位区域。

### 3 判断直径圆能否覆盖

以 `ab` 为直径，圆心和半径分别为：

```text
o = (a + b) / 2
r = D / 2
```

检查所有多边形顶点是否满足 `||v-o|| <= r`。圆盘和定位多边形都是凸集，所以圆盘包含全部顶点，当且仅当圆盘包含整个定位区域。

等价的 Thales 判据是：

```text
(v-a) · (v-b) <= 0
```

若某个顶点的点积为正，它就在直径圆外，圆不能覆盖定位区域。任取一个距离为 D 的最远点对即可完成判断：任何半径为 D/2 且覆盖区域的圆若同时包含这两个相距 D 的点，其圆心只能是这两个点的中点。

## 数学结论

以定位区域直径为直径的圆不一定覆盖定位区域。边长为 2 的等边三角形，其区域直径为 2，但任一边中点到第三个顶点的距离为 √3，大于圆半径 1，因此不能覆盖。程序必须实际检查全部顶点，不能只计算出直径后直接回答“能”。

```powershell

python -m unittest discover -s B/q1/tests -v
```

`python` 应指向已安装依赖的解释器。上述命令适用于克隆仓库后的环境，不需要本机的 `.modeling-deps`。算法仅提供 Python 函数，无 CLI 入口。调用方检查返回字典的 `status` 后读取几何结果。

Python 调用：

```python
from B.q1 import solve_bearings

result = solve_bearings([
    {"position": {"x": 0, "y": 0}, "svd_deg": 53.13010235415598},

```

## 输入输出约定

`solve_bearings(observations, error_deg=1.0, tolerance_m=1e-7)` 接收观测字典列表。每条观测必须且只能包含 `position: {x, y}` 与 `svd_deg`。所有坐标单位为米；示向度从正东方向逆时针计量，角度自动归一化，跨越 0° 不需要特殊处理。不接受 NaN、Infinity 或布尔值冒充数值。

默认误差半宽为题设的 **1°**。可显式传入 `error_deg=1.005` 研究接口保留两位小数的量化裕量；这不是题设误差范围，也不是第一问默认值。半宽需满足 `0 < error_deg < 90`。

主要输出字段：

| 字段 | 含义 |
| --- | --- |
| `status` | `BOUNDED`、`EMPTY`、`UNBOUNDED` 或 `NUMERICAL_ERROR` |
| `vertices` | 逆时针顶点，从字典序最小点开始；不重复首点 |
| `dimension` | 点为 0，线段为 1，二维多边形为 2 |
| `area_m2` | 区域面积，点和线段为 0 |
| `diameter_m`、`diameter_pair` | 最大顶点间距及对应最远点对 |
| `diameter_circle` | 最远点对中点为圆心、D/2 为半径；附最大顶点距离和覆盖差值 |
| `diameter_circle_covers` | 在显式米制容差下是否覆盖所有顶点 |
| `minimum_enclosing_circle` | 最小包围圆的圆心和重新核算的覆盖半径 |
| `tolerance_m` | 几何比较容差，默认 `1e-7` 米 |

EMPTY、UNBOUNDED、NUMERICAL_ERROR 的顶点和圆等几何字段为 `null`；无界区域数学直径为无穷大，JSON 不写非标准的 Infinity。仅 BOUNDED 时读取有限直径。`solve_halfplanes(A, b)` 为可复用的二维半平面入口。

## 半平面公式

观测点为 s、示向度为 θ、误差半宽为 δ，令 l = (cos(θ−δ), sin(θ−δ))、r = (cos(θ+δ), sin(θ+δ))。前向角域由两条约束给出：

```text
(l_y, -l_x) · x <= (l_y, -l_x) · s
(-r_y, r_x) · x <= (-r_y, r_x) · s
```

圆盘是凸集，包含所有顶点等价于包含整个凸多边形。等价覆盖判据为对全部顶点 v 检查 `(v-a)·(v-b) <= 0`。程序输出距离形式的残差 `coverage_gap_m = 最大顶点距离 - D/2`，便于复核容差边界。

程序还输出 `outside_vertex_indices` 和 `max_thales_dot_m2`。前者列出直径圆外的顶点编号；后者是 `(v-a)·(v-b)` 的最大值。最大值不大于 0 表示所有顶点位于以 ab 为直径的圆内或圆上；正值表示至少一个顶点在圆外。

附加的最小包围圆采用小规模参考算法，枚举单点、点对中点、非共线三点外心；对每个候选圆心重新计算到全部顶点的最大距离，并选择最小者。

## 正确性确认

算法的数学依据和程序实现已经按以下层次核对：

1. **定位区域正确性**：每条 ±1° 前向角域准确转换为两个半平面；跨 0°、负坐标和前向性均有专项测试。随机生成的真实干扰点均被对应角域交集包含。
2. **直径正确性**：凸多边形直径在顶点对上取得。40 组固定种子的随机测向案例与独立的逐边多边形裁剪算法比较，顶点和直径一致。
3. **覆盖判定正确性**：除解析矩形和等边三角形外，新增 200 个固定种子的随机三角形，用最大边所对角的勾股/Thales 符号作为独立判据，逐例与程序结论比较。
4. **最小包围圆复核**：10 组随机点集与独立 SLSQP 约束优化结果比较，半径一致。
5. **边界状态**：覆盖点、线段、空集、全平面、楔形、条带、直线、射线、近平行测向、重复约束、极大平移和数值异常。

完整测试共 18 项；所有随机测试都使用固定种子，可以重复运行。测试全部通过后，第一问算法在当前题设、输入约定和浮点容差范围内确认正确。

## 方案对比与最终选型

另一份算法设计提出的数学主线与当前实现相同，主要差异在工程取舍：其正式算法使用旋转卡壳计算直径、随机增量法计算最小包围圆，并建议用随坐标尺度变化的相对容差；当前实现使用线性规划判断空集和无界、枚举全部顶点对计算直径，并确定性枚举最小包围圆。

第一问定位区域的顶点数量很少，当前选择以正确性和可复核性为优先：

| 子任务 | 最终采用方案 | 选择原因 |
| --- | --- | --- |
| 空集与无界判断 | 线性规划检查可行性，并分别检查 x、-x、y、-y 四个方向 | 能明确区分 `EMPTY`、`UNBOUNDED` 和 `NUMERICAL_ERROR` |
| 定位多边形 | 边界交点枚举、全约束筛选、去重和 Andrew 凸包 | 结构直接，便于逐顶点核验 |
| 区域直径 | 枚举全部顶点对，复杂度 O(v²) | 顶点少，速度足够；比旋转卡壳更容易处理退化和并列情况 |
| 直径圆覆盖 | 顶点到圆心距离判据，附加 Thales 点积诊断 | 距离残差单位为米，结论直观；点积可独立复核 |
| 最小包围圆 | 枚举单点、点对中点和三点外心 | 确定性、容易复现；在小规模顶点集上耗时可忽略 |

旋转卡壳和随机增量最小包围圆保留为规模扩大后的优化选项。只有在性能测试表明当前枚举成为瓶颈时才替换，并必须继续用当前实现作为校验基准。论文和代码应保持一致，当前版本不能写成已经采用旋转卡壳。

文档中提出的覆盖系数适合吸收到结果解释中：

```text
K = 2R*/D
```

其中 `R*` 是最小包围圆半径。`K=1` 表示存在半径为 `D/2` 的覆盖圆，即直径圆可以覆盖；`K>1` 表示直径不足以描述覆盖需求。当前输出字段 `minimum_enclosing_circle.radius_to_half_diameter_ratio` 就是 K。

尺度化容差适合作为正式提交前的数值增强。建议覆盖比较最终采用：

```text
EPS = max(绝对长度容差, 相对容差 × D, 机器精度 × 坐标尺度)
```

当前代码已经通过法向量归一化、平移后求交和固定米制容差降低误差，并通过极大坐标平移测试；在改用尺度化容差前，不应在总结中声称代码已经实现该增强。后续问题的 `clear_ready_18m`、`clear_ready_20m` 属于策略层判断，不并入第一问接口，避免把定位几何和清除决策耦合。

## 多检测点验证案例

测试覆盖解析矩形、等边三角形反例、点和线段、空集、全平面/楔形/条带/直线/射线无界情形、前向性、跨 0°、近乎平行测向、负坐标、平移缩放、重复观测、逐步加约束单调性和异常输入。另有两组各含 6 个检测点的合成案例：

| 案例 | 直径 D | 覆盖差值 | 最小圆半径/(D/2) | 定位区域特征 | 结论 |
| --- | ---: | ---: | ---: | --- | --- |
| `multi_station_covers.json` | 47.9448m | 约 0m | 1.0000 | 5 个顶点呈长条或钝形；所有顶点对直径端点的 Thales 点积均不大于容差 | 覆盖 |
| `multi_station_not_covers.json` | 22.8974m | 4.5403m | 1.0564 | 5 个顶点中存在偏离直径中点的突出顶点；最大 Thales 点积为正 | 不覆盖 |

两组都使用合成真值 `(250,-150)`，各示向度由对应检测点到真值的真实方位叠加 `injected_errors_deg` 中对应误差得到，且误差绝对值均小于 1°。真值和注入误差只用于测试检查，算法输入仍只有 `observations` 中的检测点和示向度，以及统一误差界。

随机验证中裁剪用的大边界框会检查其是否未激活；正式求解算法不使用该边界框。

若有 n 条半平面、v 个凸包顶点，交点筛选为 O(n³)，直径计算 O(v²)，参考最小包围圆 O(v⁴)。这是少量检测点的透明参考实现，大规模控制循环应另行换用更高效算法并保留本实现做对照。

数值使用浮点而非严格区间计算：法向量归一化，HiGHS 原始/对偶可行性容差为 `1e-9`，几何容差默认 `1e-7m`；夹角极小、极大坐标或极窄区域可能存在误差。容差内合并顶点会使小于容差的区域退化为点或线段。`diameter_circle_covers` 是容差判定，不应当作任意精度的严格数学证书。程序会对主要数值异常返回 NUMERICAL_ERROR，仍不能保证检测所有病态输入。

第一问区域不额外裁入半径 1800m 的目标圆、接收圆或其他物理排除区域。代码没有实现问题二至四的搜索策略，也没有将最小包围圆直接用于自动清除。
