# Q3 V5：全局发现与动态顺路定位

## 版本定义

- 发布目录：`B/Q3 V5`。
- 运行策略标识：`v5_dynamic`，用于区分已有 v4 日志。
- 构成：当前 Q3 v4 + 已验证的 `02_dynamic_candidates` 动态候选优化。
- 没有合入成本竞争分支或复测收益分支；原有 v4 源码、实验目录和官方日志均保留。
- 干扰源简称“源”。算法只使用机器人已经获得的响应和保守可行区域，不读取干扰源真实坐标。

## 算法流程

1. 在七个覆盖站逐信道发现干扰源。记录无信号证据，满足完整覆盖或源数上限条件时确认空信道。
2. 扫描期间按 v4 规则选择有价值的固定站点机会复测，收缩已发现源的可行区域。
3. 扫描结束后，为待处理区域生成可靠清除方案和安全定位候选；保留 v4 的质量判断与区域访问顺序优化。
4. V5 在原有静态定位候选之外，按机器人位置和路线提示补充动态候选。统一比较接近、测量与后续清除的时间上界。
5. 每次收到实际响应后更新区域、清除状态与剩余任务；全部信道解决并获得完成证书后退出。

## V5 的新增机制

原 v4 主要按区域版本缓存定位候选。机器人移动后会给旧候选重新计价，但未必发现新的原地测量机会或顺路测量点。

V5 补充当前位置，以及从当前位置朝另一个待处理区域可行入口方向的 1/4、1/2、3/4 点。路线目标来自现有区域和覆盖方案，仅是生成候选的提示，并非已经确定的最优路径。

新增点逐一检查：是否已测量、是否与静态候选重复、是否在保证接收区域内、是否有有效的连续响应完成时间上界。通过后才进入原有任务筛选；顺路不意味着必须采用。

| 项目 | 设置 |
| --- | --- |
| 每个区域动态候选缓存上限 | 4 个 |
| 位置或路线提示变化触发刷新 | 至少 25 m |
| 区域版本改变 | 动态缓存立即失效 |
| 每次动态评分额外预算 | 至多分配 0.2 s |
| 其他预算 | 同时受原单次定位、全局规划和外部截止时间限制 |
| 日志标记 | `decision_budget.candidate_origin` 为 `static` 或 `dynamic_route` |

实际单次几何函数具有不可抢占部分，因此这些截止时间是协作式预算，不是进程级硬实时保证。静态评分已经耗尽预算时，本轮可不补充动态候选；后续调度仍可再次尝试。

## 保留的可靠性要求

安全接收检查、保守外包区域、覆盖清除证书、每源测量与路径预算、异常条带回退以及最终完成证书均沿用原有逻辑。未降低清除精度或提前跳过未知信道验证。

V5 仍保留 v4 的 180 秒质量门槛和先选区域动作再排路线的近似。因此，增加候选不保证每张地图都更快。

## 已有证据与发布验证

动态候选实验分支此前与冻结 v4 在相同的 14 场自建离线场景中对比：各 182 个源全部清除、零 fallback。加权时间从 322.985 降至 315.903 s/源（-2.19%）；9 场更快、5 场更慢；129 次自适应定位中有 51 次使用动态候选。

以上是被合入分支的历史离线结果，不是 V5 官方模拟器成绩，也不是原十二场官方地图的重放。V5 目录的重新打包、版本标识、启动入口和离线验证结果单独记录在 `RELEASE_VERIFICATION.json`，详细输出在 `verification`。

本次 V5 发布验证（2026-09-12）：52 项回归与针对性测试全部通过；独立入口自检确认加载 `B/Q3 V5/planner.py`，默认策略为 `v5_dynamic`；V5 两场离线测试共 21 个干扰源全部清除，零 fallback。已逐文件核对原版及来源分支未修改，并确认当前 v4 与实验所用基线一致。尚未启动官方模拟器会话。

当前策略主要在全向干扰源模型下验证；没有新增定向源实验结论。下一步通过 V5 启动入口进行官方练习，保留新生成的本地日志和官方结果，再与 v4 对照。
